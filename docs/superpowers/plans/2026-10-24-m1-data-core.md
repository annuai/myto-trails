# M1 data core and read-only public site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PostGIS-backed data core (regions, trails, revisions, access assessments, condition events, media) with public-safe read access, plus the first public pages: trail detail with the go/no-go strip, region pages, sitemap and SEO metadata, all browsable from clearly-labelled sample data.

**Architecture:** Plain SQL migrations applied by a small runner. Base tables have row-level security enabled and **no anonymous policies**; the public site reads only through `public_*` views (published rows, safe columns), and server code runs those reads under `SET LOCAL ROLE anon` so the database enforces the boundary even if app code is wrong. Business rules (effective verification level, effective condition, GPX downloadability, region indexability, slugs) are pure functions in `packages/domain`. Page data loaders are split into uncached SQL functions (tested against a real database) and thin `'use cache'` wrappers.

**Tech Stack:** PostgreSQL 17 + PostGIS (local cluster via Homebrew; `postgis/postgis` service container in CI), `postgres` (postgres.js) driver, Zod, Next.js 16 App Router with `cacheComponents`, Vitest + Testing Library.

**Spec:** `docs/06-data-model.md` (entities, lifecycles, constraints), `docs/03-information-architecture.md` (URLs, page inventory), `docs/07-ux-wireframes.md` §4 (trail detail), `docs/09-design-system.md` (components), `docs/11-security-and-moderation.md` (access rules), `docs/12-implementation-roadmap.md` (M1), `docs/05-technical-architecture.md`. Next.js 16 behaviour: read the relevant pages in `node_modules/next/dist/docs/01-app/` (caching, `use cache`, metadata, sitemap, `generateStaticParams`) before writing page code; this version differs from older Next.js.

## Global Constraints

- Everything from `docs/superpowers/plans/2026-10-24-m0-foundations.md` Global Constraints still applies (tokens only, no hex outside `packages/tokens`, sentence case, WCAG 2.2 AA, 44px targets, UUID object keys, commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`).
- Product name in all copy: **Moto Trails**; parent brand **Myto**. Canonical host `https://moto-trails.com` via `getSiteUrl`.
- Trail URL: `/trails/{slug}`; slug matches `^[a-z0-9]+(-[a-z0-9]+)*$`, max 80 chars. Region URLs: `/regions`, `/regions/{state}`, `/regions/{state}/{district}`.
- Access class values: `public | permission_required | private_no_access | restricted | unknown`. Operational status: `open | temporarily_closed | permanently_closed | seasonal | unknown`. Verification level: `officially_verified | moderator_verified | community_reported | unverified`. Difficulty: `easy | moderate | hard | expert`. Terrain: `dirt | gravel | mud | sand | rock | forest_track | mountain_road | riverbed | mixed`. Route shape: `loop | out_and_back | point_to_point`. Sensitivity: `standard | sensitive | restricted_geometry`. Lifecycle: `draft | in_review | published | unpublished | archived`.
- Constraints from doc 06: name 3–80 chars; summary 40–400 chars; at least one terrain; `best_months` values 1–12; `valid_until` after `verified_at`; start point inside India's bounding box (lon 68–98, lat 6–37).
- Verification expiry: `officially_verified` and `moderator_verified` expire at `valid_until`; for 30 days after expiry the level stays but shows "needs re-check"; after that it displays as `unverified` with "needs re-check". `community_reported` and `unverified` never expire.
- A temporarily closed condition whose `expected_until` has passed displays as `unknown`.
- GPX downloadable only if: published, has GPX, sensitivity `standard`, access class `public` or `permission_required`, condition not `permanently_closed`. (No GPX exists in M1; the rule is implemented and tested now.)
- Region pages are indexable only with ≥ 3 published trails; otherwise `noindex` and excluded from the sitemap. A permanently closed trail still returns 200 with a closed notice (never 404); unknown or unpublished slugs return 404.
- Anonymous database role can read only `public_*` views. No sample trail may be published in production.
- Public pages never expose `permission_contact`, evidence files, `start_point` of non-standard-sensitivity trails, or unpublished revisions.
- Secrets/DB URLs only in `.env.local` / CI secrets; `DATABASE_URL` is required in production (startup guard).

## Review Focus

1. **Anonymous reads of private data:** direct SQL as role `anon` must not read base tables, drafts, unpublished trails, evidence or `permission_contact`. Test in Task 4.
2. **Expired information shown as current:** expired verification and an overdue temporary closure must display as "needs re-check" / `unknown`, including on the exact boundary instants. Test in Task 2 and Task 8.
3. **Sensitive-trail location:** a `sensitive` trail must expose only its approximate `public_point` in views, pages and JSON-LD, never `start_point`. Test in Tasks 4, 7 and 10.
4. **Hostile or odd URLs:** unknown slug, uppercase, trailing slash, 200-char slug, SQL metacharacters and unicode in `[slug]`/`[state]`/`[district]` return 404 (not 500) and are always passed as query parameters. Test in Task 7.
5. **Thin and degenerate region pages:** regions with 0, 1 or 2 published trails are `noindex` and absent from the sitemap; a state with no districts renders; unknown region 404s. Test in Tasks 7 and 9.
