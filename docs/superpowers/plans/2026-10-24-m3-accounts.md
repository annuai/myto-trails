# M3 accounts, saved trails and reports Implementation Plan (condensed)

> Executed inline, test-first, one fresh whole-branch review at the end. Autonomous run: decisions are recorded as rulings in the final report.

**Goal:** Passwordless accounts, a Saved list that shows when a saved trail changes, and "Report an issue" with a visible warning for reported closures.

**Spec:** docs/02 (U-1…U-3, R-1…R-4), docs/03, docs/06 (collection, trail_report), docs/07 §5, docs/11.

## Decision: own passwordless auth (deviation from ADR 0002)
No Supabase or Google credentials exist yet, so authentication is built in the application database: email sign-in links, hashed tokens, hashed session tokens in an HTTP-only cookie. It sits behind small interfaces (`EmailSender`, session store) so a provider can replace or complement it. Google sign-in needs OAuth credentials and stays unbuilt. Recorded as ADR 0005.

## Global constraints
- Tokens: 256-bit random, only the SHA-256 hash stored. Sign-in link valid 15 minutes, single use; the link opens a confirmation page and consuming happens on a POST, so email scanners cannot use it up.
- Session cookie `mt_session`: HttpOnly, SameSite=Lax, Secure in production, 30 days; new session on every sign-in; sign-out deletes it server-side.
- `next` redirect targets are same-site paths only (`/…`, never `//`, backslashes or schemes).
- User tables are closed to the anonymous role; account data is read only through functions that take the user id from the verified session.
- Rate limits (database-backed): sign-in requests 5 per hour per email and 20 per hour per IP hash; reports 10 per day per user.
- Sign-in responses never reveal whether an address has an account.
- Report details 20–2000 characters; reporter identity is never exposed publicly.
- Email provider `EMAIL_PROVIDER=console|resend` (console only outside production; production requires resend config).

## Tasks
1. **Schema (0007):** `app_user`, `user_role`, `login_token`, `auth_session`, `rate_limit`, `collection`, `collection_item`, `trail_report`; all closed to anon; public view column for open closure-report count.
2. **Auth core:** token + cookie helpers, `safeNextPath`, `rateLimit`, `requestSignIn`, `confirmSignIn`, `getSessionUser`, `signOut`, email interface with console and Resend senders; DB tests (single use, expiry, rate limits, session expiry, no enumeration).
3. **Account UI:** `/sign-in`, `/sign-in/check-email`, `/auth/confirm`, `/account` (display name, sign out), header account area in Suspense.
4. **Saved:** queries (`saveTrail`, `unsaveTrail`, `listSaved` with change detection, `markSavedSeen`) with cross-user isolation tests; `SaveButton`, `/saved` page, "Changed" badges.
5. **Reports:** schema validation, `createReport` with rate limit and priority, report page and form, closure warning notice on the trail page; DB tests.
6. **Verification and review.**

## Review focus
1. Token and session security: single use, expiry boundaries, hashing, fixation, cookie flags, logout.
2. Open redirects and CSRF on sign-in/out, save, report actions.
3. Account enumeration and rate-limit bypass (email case, +tags, IP header spoofing).
4. Cross-user data access in Saved and reports; anon access to user tables.
5. Reporter privacy: no reporter identity in any public view or page.
