# M9 public API Implementation Plan (condensed)

> Executed inline, test-first, one fresh review at the end. Autonomous run: decisions are recorded as rulings in the final report.

**Goal:** A versioned `/api/v1` that a companion app or a Myto Navi unit can use with a revocable device token: read trails, download GPX, manage Saved, upload files, create and submit trail drafts, send reports, and sync Saved changes. Published as an OpenAPI description.

**Spec:** docs/14 (platform contract), docs/06 (device), docs/12 M9, docs/11 (limits).

## Decisions
- **Device tokens, not OAuth.** OAuth with PKCE needs the companion app and an identity provider; neither exists. A signed-in rider creates a token on `/account/devices` (shown once, stored only as a SHA-256 hash), picks a kind (`app_ios`, `app_android`, `navi`) and a label, and can revoke it. Scopes: `read` (public data), `saved` (read/write Saved), `write:submission` (uploads, drafts, reports). Replacing this with OAuth later does not change the endpoints.
- **Public reads need no token** (same data as the website, same query layer, same rules: sensitive trails expose no geometry, GPX only when `canDownloadGpx`). A token raises the rate limit and is required for anything about the user.
- **One error shape:** `{ "error": { "code": "...", "message": "..." } }`; codes are stable strings.
- **Idempotency:** drafts take a client-generated `client_id` (UUID); repeating returns the same draft.
- **Limits:** per-token and per-IP rate limits through `rate_limit_hit`; request bodies capped (64 KB JSON).
- **Sync:** `GET /api/v1/sync?since=<ISO time>` returns the user's Saved trails changed since then (condition, access, verification, published version), plus removed/unpublished slugs, so a device can refresh offline copies.
- **No CORS for credentials.** Tokens are bearer headers only; no cookies are read by `/api/v1`, so CSRF does not apply.

## Tasks
1. **Schema 0013:** `api_token`; DB tests.
2. **Token service:** create (returns plaintext once), verify (hash lookup, revoked, user active, scopes, `last_used_at`), revoke, list; tests incl. suspended user.
3. **HTTP layer:** `handle()` wrapper (auth, scopes, rate limit, errors, size cap, JSON), endpoints, tests of handlers with a real database.
4. **Account UI:** `/account/devices` create/revoke.
5. **OpenAPI:** `/api/v1/openapi.json` generated from one route table, with a test that every route is described and vice versa.
6. **Review.**

## Review focus
1. A revoked, expired-by-suspension or wrong-scope token never gets data; token comparison and logging never expose plaintext.
2. Endpoints cannot leak other users' saved/submission data or moderator-only fields; ids from the URL are always scoped to the token's user.
3. Public endpoints cannot be used to read sensitive-trail geometry or non-downloadable GPX.
4. Idempotent retries and rate limits behave; oversized and malformed bodies get clean 4xx errors.
5. The OpenAPI file matches the real behaviour (status codes, shapes).
